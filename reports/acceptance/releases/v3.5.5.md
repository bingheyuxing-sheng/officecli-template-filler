# v3.5.5 — 审阅修订 ID 与版面检查修复

- 版本：**v3.5.5**
- 发布日期：2026-11-02
- 发布类型：**正式版**
- 对应提交：`e8053b5`（附注 tag `v3.5.5`）

## 一句话

这个版本修复了两个在全链路验证中发现的问题：同一段落里格式修订和文字修订的 ID 冲突，以及修订后的文档被版面检查误判为失败。

## 这个版本修复了什么

- **修订 ID 冲突**：同一段落既有格式修复又有文字修订时，拆分 Run 会把同一个 `w:rPrChange` 的 `w:id` 复制到 prefix / `w:del` / `w:ins` / suffix 副本里，导致审阅完整性检查报 `duplicate revision ids`，审阅事务被中止。现在只有第一个副本保留格式修订标记，其余副本剥离，保证每个 `w:id` 唯一。
- **版面检查误报**：`run_qa.py --review --reference` 把修订拆分后的 Run 数量和批注故事段落计入版面指纹，导致合法的审阅文档被判 `FAILED`。现在按“接受修订后”的视图计数，忽略 `w:del` / `w:moveFrom` 和批注引用，合并同格式相邻 Run，批注故事不参与版面对比。

## 验证

- GENERATE（含负向中止）、REPAIR、REVIEW、PROOFREAD、EXCEL_GENERATE、输入路由、能力拦截、进程清理日志共 20 个端到端场景全部通过。
- 新增审阅格式修订与文字修订同段落的 ID 唯一性测试，以及修订 / 批注感知的版面指纹测试。

## 测试结果

- **111 项全部通过**。
